# شهرزاد (Shahrzad)

[English](README.md) | **فارسی**

شهرزاد یک مترجم ادبی محلی و عاملی (agentic) از انگلیسی به فارسی ایرانی برای کتابخانهٔ شخصی است. یک فایل EPUB (ترجیحاً) یا PDF دارای لایهٔ متن، یا DOCX/TXT/Markdown را به آن بدهید تا فایل‌های فارسی باز و قابل‌ویرایش تولید کند: EPUB 3 (راست‌به‌چپ)، DOCX (راست‌به‌چپ)، Markdown و متن ساده. HTML دوزبانه و تبدیل DOCX به PDF اختیاری هستند.

این برنامه یک CLI محلی (`shz`) است؛ بدون سرور، بدون رابط وب و بدون تله‌متری. ترجمه به‌طور پیش‌فرض کاملاً خودکار است؛ تأیید بریف، بازبینی واژه‌نامه، تنظیم لنگرها و بازبینی انسانی دروازه‌های اختیاری‌اند. سقف هزینهٔ پیش‌فرض **۱۰ دلار برای هر کتاب** است و `shz estimate` هزینهٔ تخمینی را پیش از هر خرجی نشان می‌دهد.

## نحوهٔ کار

شهرزاد یک خط لولهٔ قطعی و قابل‌ازسرگیری است، نه یک حلقهٔ عامل آزاد. فرمان‌های پردازشی یک توالی ثابت از پاس‌ها را روی یک پایگاه‌دادهٔ SQLite اجرا می‌کنند و هر فراخوانی LLM اعتبارسنجی طرح‌واره‌ای، کش، انتساب و هزینه‌گذاری می‌شود. مشخصات منجمد در [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) بخش‌های ۳.۴ و ۶.۳–۶.۷ آمده است؛ این بخش خلاصهٔ کاری است.

### خط لوله در یک نگاه

```mermaid
flowchart LR
    A[shz init<br/>استخراج · فصل‌بندی · قطعه‌بندی] --> B[shz analyze (اختیاری)<br/>بریف · خلاصه‌ها · موجودیت‌ها · واژه‌نامه]
    A --> C[shz translate<br/>پنجره‌ها · پیش‌نویس · نقد · بازنگری · ترمیم]
    B --> C
    C --> D[shz audit<br/>ممیزی قطعی · پیوستگی نمونه‌ای · خوانش کامل]
    D --> E[shz review (اختیاری)<br/>ویرایش انسانی]
    E --> F[shz export<br/>EPUB · DOCX · MD · TXT]
    D --> F
```

| مرحله | چه کاری می‌کند | فراخوانی‌های LLM |
|---|---|---|
| `shz init` | منبع را استخراج، فصل‌بندی و به قطعه‌های دارای شناسهٔ پایدار تقسیم می‌کند، نشانه‌گذاری درون‌خطی و تخمین توکن را ثبت می‌کند و `book.db` را می‌نویسد. PDFها امتیاز کیفیت ورود هم می‌گیرند. | هیچ |
| `shz analyze` (اختیاری) | بریف کتاب، خلاصهٔ فصل‌ها، فهرست موجودیت‌ها و کاندیدهای اختیاری واژه‌نامه را می‌سازد. بدون بریف تأییدشده، ترجمه از پیش‌فرض‌های محافظه‌کارانهٔ داخلی استفاده می‌کند و اجرا را `experimental` علامت می‌زند. | A1–A4 |
| `shz translate` | پنجره‌ها را برنامه‌ریزی می‌کند، برای هر پنجره بستهٔ زمینه می‌سازد، سپس پیش‌نویس، نقد، بازنگری، ترمیم و لینت انجام می‌دهد. در پایان هر فصل دفتر پیوستگی را هم می‌آراید. | A5–A9 |
| `shz audit` | ممیزی قطعی واژه‌نامه/نام‌ها را اجرا می‌کند، برای ممیز پیوستگی از پنجره‌ها نمونه می‌گیرد، هر فصل فارسی را بدون متن مبدأ می‌خواند و خطاهای هدفمند ممیزی را ترمیم می‌کند. | A10–A11 و A8 برای ترمیم |
| `shz review` (اختیاری) | گزارش HTML خودبسنده از قطعه‌های علامت‌خورده می‌سازد؛ اعمال اصلاحات، آن‌ها را به‌صورت نسخه‌های انسانی ذخیره و QA را دوباره اجرا می‌کند. | هیچ |
| `shz export` | تبدیل فقط‌خواندنی پایگاه‌داده به EPUB 3 راست‌به‌چپ، DOCX راست‌به‌چپ، Markdown و متن ساده (به‌همراه HTML دوزبانه و PDF اختیاری)، با اعتبارسنجی داخلی. | هیچ |

### واحدها: قطعه‌ها و پنجره‌ها

پاراگراف واحد ترجمه است؛ یک **قطعه (segment)** می‌تواند پاراگراف، عنوان، بند شعر، ردیف جدول یا متن پانویس باشد. شناسه‌های پایدار (`c003.s0042`) متن مبدأ و ترجمه را هم‌تراز نگه می‌دارند و هر پاس را قابل‌ازسرگیری می‌کنند.

یک **پنجره (window)** همان تکهٔ قطعی است که یک فراخوانی LLM می‌بیند (اصطلاح کد برای «chunk»):

- حداکثر **۸ قطعه** و **۹۰۰ توکن مبدأ** به‌طور پیش‌فرض (`pipeline.window.max_paragraphs` و `max_source_tokens`)؛
- هیچ قطعه‌ای بین پنجره‌ها شکسته نمی‌شود؛ یک قطعهٔ بیش‌ازحد بزرگ پنجرهٔ مستقل خودش می‌شود؛
- نخستین عنوان هر فصل دست‌کم با یک بلوک بعدی همراه می‌شود؛
- پاراگراف‌های دیالوگ مجاور در صورت اجازهٔ بودجه کنار هم می‌مانند؛
- هر پنجره **۲** قطعهٔ قبلی (هم متن مبدأ و هم فارسی نهایی) را فقط به‌عنوان زمینه حمل می‌کند؛ این هم‌پوشانی هرگز دوباره ترجمه نمی‌شود.

پنجره‌ها به ترتیب خواندن برنامه‌ریزی و هش می‌شوند. درون هر فصل **کاملاً ترتیبی** اجرا می‌شوند، چون زمینهٔ هر پنجره خروجی پنجرهٔ قبلی را در بر می‌گیرد؛ فصل‌ها را می‌توان با `--parallel-chapters` موازی کرد. طرح در مانیفست اجرا ذخیره می‌شود و طرح تغییریافته رد می‌شود مگر آنکه `shz translate --replan` را بدهید.

### حلقهٔ ترجمه (برای هر پنجره)

```text
ساخت بستهٔ زمینه
  → پیش‌نویس A5
  → منتقد وفاداری A6  +  ویراستار ادبی A7
  → بازنگری A8 (فقط موارد نقل‌شده، حداکثر ۱ دور)
  → ترمیم قطعی (فقط خطاهای لینت، حداکثر ۲ دور)
  → لینت قطعه + پنجره، امتیاز ریسک، به‌روزرسانی وضعیت
  → پنجرهٔ بعدی
```

1. **بستهٔ زمینه.** یک پیشوند پایدار (قواعد سیستم، کارت بریف، واژه‌نامهٔ تأییدشده، لنگرهای صدا) به‌همراه زمینهٔ متغیر (خلاصهٔ فصل، خلاصهٔ غلتان فصل، مدخل‌های مرتبط دفتر پیوستگی، دو قطعهٔ قبلی و متن پنجره). پیشوند بایت‌به‌بایت پایدار است تا کش اعلان ارائه‌دهنده فعال شود.
2. **پیش‌نویس.** A5 قطعه‌های در انتظار پنجره را در یک پاسخ ساختاریافتهٔ `TranslatorOutput` ترجمه می‌کند؛ شناسه‌های قطعه باید دقیقاً بخوانند و شناسه‌های گم‌شده دوباره درخواست می‌شوند، نه اینکه از خود ساخته شوند.
3. **بازبینی.** A6 (وفاداری) و A7 (ویراستار ادبی) هرکدام **یک بار برای هر پنجره** اجرا می‌شوند و یافته‌های نقل‌شدهٔ هر قطعه را برمی‌گردانند. این همان مرز تکهٔ پیش‌نویس است، بنابراین بازبینی نه برای هر فصل و نه برای هر پاراگراف جداگانه انجام نمی‌شود.
4. **بازنگری.** A8 فقط یافته‌های مشخص و تأییدشده را اعمال می‌کند، به‌طور پیش‌فرض یک بار برای هر پنجره (`critics.max_revision_rounds: 1`). یک نگهبان پس‌رفت، بازنگری‌ای را که به نشانه‌گذاری آسیب بزند، متن را خالی کند، خطای لینت تازه بسازد یا از محدودهٔ طول بیرون بزند رد می‌کند و پیش‌نویس را نگه می‌دارد.
5. **ترمیم.** خطاهای قطعی لینت حداکثر دو دور ترمیم هدفمند A8 را برای هر پنجره فعال می‌کنند و فقط قطعه‌های ناموفق را پوشش می‌دهند.
6. **بررسی.** لینت‌های سطح قطعه و پنجره اجرا می‌شوند، ایرادها حذف تکراری می‌شوند، امتیاز ریسک محاسبه می‌شود و هر قطعه از `drafted` به `done` می‌رود (یا در صورت نیاز به توجه، به `flagged`/`failed`). بازنگری یا ترمیم نسخهٔ تازه‌ای می‌افزاید بدون دور ریختن تاریخچه.

حالت `economy` از A7 صرف‌نظر می‌کند و A6 را فقط وقتی خطای طول (`L08`) وجود دارد اجرا می‌کند؛ `standard` هر دو منتقد را اجرا می‌کند؛ `quality` مدل A6/A7/A8 را به ردهٔ کیفیت منتقل می‌کند. هر پاس یک درخواست تازه است — زمینه از پایگاه‌داده بازسازی می‌شود و هرگز به‌صورت تاریخچهٔ گفتگو حمل نمی‌شود — بنابراین یک پنجره را می‌توان بدون آلودگی متقابل دوباره اجرا یا ازسرگیری کرد.

### پیوستگی بین پنجره‌ها و فصل‌ها

- **بریف** — صدا، لحن، خطاب و سیاست پانویسِ منجمدشده (A1).
- **واژه‌نامه** — اصطلاحات تأییدشده به بسته تزریق می‌شوند؛ وقتی خاموش است، به‌جای آن از فهرست قطعی اسم‌های خاص استفاده می‌شود.
- **خلاصهٔ فصل** — خلاصهٔ انگلیسی فصل (A2).
- **خلاصهٔ غلتان** — چند جملهٔ فارسی پایانی فصل که دوره‌ای تازه می‌شود.
- **دفتر پیوستگی** — شخصیت‌ها، اصطلاحات، تصمیم‌ها و پرسش‌های باز؛ A9 آن را در پایان فصل می‌آراید و بسته‌ساز فقط برش مرتبط با پنجرهٔ جاری را تزریق می‌کند. در حالت `--parallel-chapters` زنجیره‌سازی دفتر غیرفعال است و پیوستگی به خلاصه‌های پیش‌محاسبه‌شده تکیه می‌کند.
- **لنگرها** — جفت‌های اختیاری و تأییدشدهٔ مبدأ/فارسی برای صدا، از فصل ۱.

پس از هر فصل، L15 سنجه‌های سبک فارسی (طول قطعه، نسبت دیالوگ، نسبت واژه‌های یکتا) را با خط پایهٔ در حال اجرای کتاب مقایسه می‌کند و دربارهٔ رانش سبک هشدار می‌دهد.

### بازبینی ترجمه در برابر بازبینی ممیزی

این دو عمداً دامنه‌های متفاوتی دارند:

- **درون `shz translate`، بازبینی و بازنگری برای هر پنجره‌اند** — A6، A7 و A8 هر بار یک پنجره را می‌بینند، با همان هم‌پوشانی و بستهٔ زمینهٔ پیش‌نویس.
- **`shz audit` در سطح فصل/کتاب است.** A10 برای یافته‌های پیوستگی از حداکثر `--sample N` پنجره در هر فصل (پیش‌فرض ۳) نمونه می‌گیرد؛ A11 **کل فصل فارسی** را بدون متن مبدأ دریافت می‌کند تا ترجمه‌وارگی و مشکلات ریتم را بگیرد؛ ممیزی‌های قطعی همهٔ قطعه‌ها را می‌گردند؛ و ترمیم‌های ممیزی در سطح قطعه‌اند.
- **`shz review` در سطح قطعه‌های علامت‌خورده است.** انسان قطعه‌های مستقل را در `review/report.html` ویرایش می‌کند؛ `shz review apply` یک نسخهٔ `pass=human` درج می‌کند و لینت‌ها را دوباره اجرا می‌کند.

### وضعیت، ازسرگیری و قطعیت

`book.db` منبع حقیقت است: فصل‌ها، قطعه‌ها، نسخه‌های فقط‌افزودنی ترجمه (پیش‌نویس، بازنگری، ترمیم، انسانی)، ایرادهای باز، واژه‌نامه، دفتر پیوستگی، آمار اجرا و کش پاسخ. اجرای دوبارهٔ یک پنجرهٔ تغییرنکرده پاسخ‌های کش‌شده را دوباره استفاده می‌کند و نسخهٔ تازه‌ای نمی‌سازد. هر فراخوانی مدل، هش اعلان، توکن، هزینه و تأخیر را ثبت می‌کند، بنابراین اجرا می‌تواند در سقف بودجه متوقف و دقیقاً از همان‌جا ازسرگیری شود. در حالت ترتیبی، همان پایگاه‌داده، مصنوعات و پیکربندی همان طرح پنجره، کلیدهای کش و خروجی‌ها را تولید می‌کنند.

برای مشخصات کامل — بودجهٔ بستهٔ زمینه، فهرست لینت‌ها، سیاست شدت، ماشین‌های حالت و قواعد خروجی — به [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) و [`SCHEMAS.md`](SCHEMAS.md) مراجعه کنید.

## پیش‌نیازها

- **Python 3.12** و [`uv`](https://docs.astral.sh/uv/).
- کلیدهای API برای ارائه‌دهنده‌های پروفایل مدل: `DEEPSEEK_API_KEY` (پیش‌فرض `deepseek-flash`) و `OPENROUTER_API_KEY` (ردهٔ `quality`). کلیدها از محیط یا `.env` خوانده می‌شوند و هرگز چاپ نمی‌شوند.
- اختیاری: **LibreOffice** (`soffice`) برای `--pdf` و **Java + epubcheck** برای اعتبارسنجی بیرونی EPUB.
- هیچ سرور پایگاه‌داده، دانلود مدل یا سرویس سیستمی لازم نیست. مجموعهٔ آزمون و `shz doctor` بدون کلید و آفلاین کار می‌کنند.

## نصب

```bash
uv sync
cp .env.example .env          # PowerShell: Copy-Item .env.example .env
uv run shz doctor
```

کلیدهایی را که استفاده می‌کنید در `.env` پر کنید (در git نادیده گرفته می‌شود). `shz doctor` بدون چاپ مقدار کلیدها می‌گوید کدام‌یک حاضر است و وقتی تنها یافته‌ها هشدار باشند با کد `0` خارج می‌شود.

## آموزش: EPUB یا PDF دارای لایهٔ متن

فرمان‌های زیر سطح دقیق v1 هستند. می‌توانید آن‌ها را از ریشهٔ پروژه با `uv run shz …` اجرا کنید، یا پس از فعال‌سازی محیط فقط `shz …`.

### ۱. ساخت فضای کار

```bash
uv run shz init book.epub --slug my-book
# یا برای PDF دارای لایهٔ متن قابل انتخاب:
uv run shz init book.pdf --slug my-book
```

`shz init` منبع را استخراج، فصل‌بندی و پاراگراف‌ها را قطعه‌بندی می‌کند و `books/my-book/book.db` را می‌نویسد. هرگز LLM را صدا نمی‌زند.

برای PDF، `shz init` امتیاز کیفیت ورود (۰ تا ۱) را ثبت می‌کند. با `shz inspect` آن را ببینید:

```bash
uv run shz --book my-book inspect
```

امتیاز کمتر از `0.6` به‌طور پیش‌فرض ترجمه را متوقف می‌کند. مرزهای فصل را در `books/my-book/artifacts/structure.yaml` اصلاح کنید، یا آگاهانه با `shz --book my-book translate --accept-pdf-quality` ادامه دهید. OCR وجود ندارد: PDF فقط‌تصویری با `PDF_NO_TEXT_LAYER` شکست می‌خورد.

### ۲. اختیاری: تحلیل، تأیید بریف و واژه‌نامه

مسیر بدون پیکربندی به این مرحله نیاز ندارد: `shz translate` به بریف محافظه‌کارانهٔ داخلی برمی‌گردد (و اجرا را `experimental` علامت می‌زند). تحلیل معمولاً صدا و پیوستگی را بهتر می‌کند.

```bash
uv run shz --book my-book analyze
```

`pipeline.analyze.brief_approval` پیش‌فرض `auto` است، بنابراین این فرمان `books/my-book/artifacts/brief.yaml` را بدون پرسش اعتبارسنجی و منجمد می‌کند. برای بازبینی دستی:

```bash
uv run shz --book my-book analyze --review-brief
# فایل books/my-book/artifacts/brief.draft.yaml را ویرایش کنید، سپس:
uv run shz --book my-book analyze --approve
```

حالت‌های واژه‌نامه اختیاری‌اند:

- `off` (پیش‌فرض): بدون واژه‌نامه و بدون مرحلهٔ تأیید؛ نام‌ها با یک فهرست قطعی اسم‌های خاص پایدار می‌مانند.
- `provided`: `shz init book.epub --glossary terms.yaml`، یا تنظیم `glossary.mode: provided` و `glossary.path` در پیکربندی کتاب.
- `auto`: `uv run shz --book my-book analyze --auto-glossary`، سپس بازبینی پیشنهادها با `shz --book my-book glossary review` و `shz --book my-book glossary approve`.

### ۳. تخمین هزینه

```bash
uv run shz --book my-book estimate
```

این فرمان جدول توکن و هزینهٔ تخمینی را برای `economy`، `standard` و `quality` در تعرفه‌های اوج و غیراوج چاپ می‌کند و هیچ فراخوانی ارائه‌دهنده انجام نمی‌دهد. با `--chapters 3` پیشوندی از کتاب را تخمین بزنید، یا با `--json` خروجی ماشین‌خوان بگیرید.

### ۴. ترجمه

```bash
uv run shz --book my-book translate
```

این فرمان همهٔ فصل‌ها را به ترتیب خواندن ترجمه می‌کند و در صورت قطع، از پایگاه‌داده ازسرگیری می‌کند. هنگام اجرا، نوار پیشرفت زنده روی stderr فصل و فاز جاری (پیش‌نویس، بازبینی، بازنگری، ترمیم، بررسی)، پنجره‌های کامل‌شده، قطعه‌های ترجمه‌شده و هزینهٔ تا این لحظه را نشان می‌دهد. در ترمینال تعاملی خودکار ظاهر می‌شود؛ با `--progress` یا `--no-progress` آن را روشن یا خاموش کنید.

پرچم‌های مفید: `--chapters 1,3-5`، `--dry-run` (فقط برنامه‌ریزی و تخمین، بدون فراخوانی)، `--max-usd 5`، `--cost-mode economy`، `--parallel-chapters 4`، `--no-cache`، `--refresh`.

کدهای خروج: `0` موفقیت، `2` خطای استفاده/پیکربندی، `3` توقف در سقف بودجه (وضعیت ذخیره می‌شود؛ سقف را بالا ببرید و دوباره اجرا کنید)، `4` پایان با ایرادهای خطای حل‌نشده یا پوشش کمتر از ۱۰۰٪ (گزارش اجرا را ببینید).

### ۵. ممیزی

```bash
uv run shz --book my-book audit
```

ممیزی، بررسی‌های نمونه‌ای پیوستگی، ممیزی قطعی واژه‌نامه/نام‌ها، ترمیم‌های هدفمند و خوانش کامل فارسی بدون متن مبدأ را اجرا می‌کند. فقط فصل‌هایی را ممیزی می‌کند که ترجمه دارند. پرچم‌های مفید: `--chapter 3`، `--sample 5`، `--no-readthrough`، `--max-usd 2`، `--json`.

گزارش در `books/my-book/runs/<run_id>/report.md` است.

### ۶. اختیاری: بازبینی انسانی

```bash
uv run shz --book my-book review build
# فایل books/my-book/review/report.html را باز کنید، قطعه‌های علامت‌خورده را ویرایش کنید،
# فایل corrections.jsonl را دانلود کنید، سپس:
uv run shz --book my-book review apply corrections.jsonl
```

بازبینی هرگز الزامی نیست و به‌تنهایی مانع برون‌بری نمی‌شود. `shz review build` یک `review/report.html` خودبسنده و `review/flags.csv` می‌نویسد؛ `shz review apply` نسخه‌های انسانی را درج، QA را دوباره اجرا و پرچم‌ها را به‌روزرسانی می‌کند.

### ۷. برون‌بری

```bash
uv run shz --book my-book export --formats epub,docx,md,txt
```

افزونه‌های اختیاری:

```bash
uv run shz --book my-book export --formats epub,docx --pdf
uv run shz --book my-book export --formats epub,docx --bilingual
uv run shz --book my-book export --allow-incomplete   # آگاهانه از دروازهٔ کامل‌بودن می‌گذرد
```

خروجی‌ها در `books/my-book/out/` با نام‌های `<slug>.fa.epub`، `<slug>.fa.docx`، `<slug>.fa.md` و `<slug>.fa.txt`، به‌همراه `<slug>.fa.pdf` (`--pdf`) و `<slug>.bilingual.html` (`--bilingual`) قرار می‌گیرند. EPUB در هر برون‌بری به‌صورت داخلی اعتبارسنجی می‌شود؛ `epubcheck` بیرونی فقط در صورت نصب اجرا می‌شود. هر کتاب برون‌برده با نشانی پروژه، `https://github.com/kavir1698/translator_agent`، پایان می‌یابد؛ شهرزاد به‌طور خودکار اعتبار «ترجمه از» اضافه نمی‌کند. فقط وقتی باید مترجم انسانی در فراداده اعتبار بگیرد از `--translator` استفاده کنید.

### ۸. نمونه: کل کتاب در حالت `quality`، فضای کار کنار فایل منبع

`--cost-mode` حالت خودکار آن اجرا را بازنویسی می‌کند: `economy` ویراستار ادبی را رد می‌کند، `standard` پیش‌فرض است و `quality` ردهٔ کیفیت پیکربندی‌شده را برای منتقدها و بازنگر نگه می‌دارد (پروفایل ارائه‌شده از `gpt-6-luna` از طریق OpenRouter استفاده می‌کند، بنابراین `OPENROUTER_API_KEY` لازم است). ابتدا `shz estimate` را اجرا کنید؛ هر سه حالت را در هر دو تعرفه چاپ می‌کند.

به‌طور پیش‌فرض فضای کار زیر `books/` در پروژه است. برای نگه‌داشتن پایگاه‌داده، مصنوعات اجرا و خروجی کنار فایل منبع، `project.books_dir` را با یک مسیر مطلق به آن پوشه اشاره دهید و سپس همان پوشه را به `--out` بدهید:

```powershell
$InputDir = "D:\library"
$Book     = Join-Path $InputDir "book.epub"
$env:SHAHRZAD_PROJECT__BOOKS_DIR = $InputDir

uv run shz init $Book --slug book
uv run shz --book book estimate
uv run shz --book book translate --cost-mode quality --max-usd 10
uv run shz --book book audit
uv run shz --book book export --formats epub,docx,md,txt --out $InputDir
```

این کار فضای کار را در `D:\library\book\` می‌سازد و `book.fa.epub`، `book.fa.docx`، `book.fa.md` و `book.fa.txt` را در `D:\library\` می‌نویسد. فرمان‌ها را از ریشهٔ پروژه اجرا کنید؛ `SHAHRZAD_PROJECT__BOOKS_DIR` به نشست جاری پوسته اعمال می‌شود. برای پیش‌فرض‌شدن، `SHAHRZAD_PROJECT__BOOKS_DIR=D:\library` را به `.env` بیفزایید. اگر دروازهٔ برون‌بری ایرادهای حل‌نشده گزارش کرد، آن‌ها را حل یا waived کنید (`shz qa`) یا آگاهانه `--allow-incomplete` را بدهید.

در bash همان بازنویسی:

```bash
export SHAHRZAD_PROJECT__BOOKS_DIR="$HOME/library"
uv run shz init "$HOME/library/book.epub" --slug book
uv run shz --book book translate --cost-mode quality --max-usd 10
uv run shz --book book export --formats epub,docx,md,txt --out "$HOME/library"
```

## مرجع فرمان‌ها

گزینه‌های سراسری: `--book/-b <slug>` (وقتی بیش از یک فضای کار وجود دارد لازم است) و `--verbose/-v`. گزینه‌های سراسری باید **پیش از** فرمان بیایند، مثلاً `shz --book my-book translate`.

| فرمان | پرچم‌ها / زیرفرمان‌ها |
|---|---|
| `shz doctor` | `--json`، `--models`، `--tokenizer`، `--epubcheck` |
| `shz estimate` | `--chapters N`، `--words N`، `--json` |
| `shz init <FILE>` | `--slug`، `--rights-basis`، `--translator`، `--glossary <FILE>`، `--force` |
| `shz inspect` | `--json`، `--diff` |
| `shz analyze` | `--sample-budget N`، `--draft-only`، `--approve`، `--only N`، `--review-brief`، `--auto-glossary` |
| `shz translate` | `--chapters`، `--segments`، `--windows`، `--dry-run`، `--exit-after N`، `--max-usd N`، `--cost-mode`، `--allow-overrun`، `--force`، `--no-cache`، `--refresh`، `--parallel-chapters N`، `--calibrate`، `--replan`، `--only-stale`، `--require-anchors`، `--no-anchors`، `--review-brief`، `--local-only`، `--allow-cloud`، `--accept-pdf-quality`، `--progress/--no-progress` |
| `shz retranslate` | `--segments`، `--chapter`، `--window`، `--stale-only`، `--progress/--no-progress` |
| `shz audit` | `--chapter N`، `--sample N`، `--readthrough/--no-readthrough`، `--max-usd N`، `--json` |
| `shz export` | `--formats epub,docx,md,txt`، `--out <DIR>`، `--allow-incomplete`، `--generated-at <ISO-8601>`، `--pdf`، `--bilingual` |
| `shz glossary` | `list`، `review`، `approve`، `reject`، `edit`، `add`، `import`، `export`، `sync`، `pending` |
| `shz qa` | `--chapter`، `--group consistency\|literary\|loss\|all`، `--stale-glossary`، `--json`؛ `accept`، `resolve` |
| `shz anchors` | `propose`، `approve`، `reject`، `list` |
| `shz review` | `build`، `apply` |

`shz translate --review-brief` فقط هشدار چاپ می‌کند و دروازهٔ اجرا نیست. دروازهٔ دستی واقعی بریف، `shz analyze --review-brief` است (که با کد `3` خارج می‌شود) و پس از آن `shz analyze --approve`. `--allow-cloud` برای اجرای کتاب‌های دارای مجوز پذیرفته می‌شود اما در v1 فقط اطلاع‌رسانی است؛ `--local-only` به `provider.profile: local` نیاز دارد.

در این ساخت **هیچ فرمان `shz eval` وجود ندارد**. هارنس ارزیابی، داور و مقایسهٔ مدل‌های توصیف‌شده در طرح پیاده‌سازی به پس از v1 موکول شده‌اند.

### `shz glossary`

| زیرفرمان | آرگومان‌ها / پرچم‌ها |
|---|---|
| `list` | `--status proposed\|approved\|rejected\|deprecated`، `--json` |
| `review` | `--min-confidence N`، `--json` |
| `approve` | `[IDS...]`، `--min-confidence N` |
| `reject` | `IDS...` |
| `edit` | `ENTRY_ID`، `--fa`، `--en`، `--kind`، `--aliases-fa`، `--note` |
| `add` | `--en`، `--fa`، `--kind`، `--aliases-en`، `--aliases-fa`، `--note` |
| `import` | `FILE`، `--honor-status` |
| `export` | `--out <FILE>` |
| `sync` | — |
| `pending` | `--json` |

انواع واژه‌نامه: `character`، `place`، `organization`، `term`، `motif`، `form_of_address`، `title`، `unit`.

### `shz qa`، `shz anchors`، `shz review`

| فرمان | آرگومان‌ها / پرچم‌ها |
|---|---|
| `shz qa accept` | `--issue ID`، `--note TEXT`، `--reviewer NAME` |
| `shz qa resolve` | `--issue ID` |
| `shz anchors approve` | `--ids a,b` (پیش‌فرض: همهٔ کاندیدها) |
| `shz anchors reject` | `--ids a,b` |
| `shz review build` | `--chapter N`، `--out <FILE>` |
| `shz review apply` | `CORRECTIONS.jsonl`، `--dry-run`، `--reviewer NAME`، `--force` |

## پیکربندی

پیکربندی به این ترتیب ادغام می‌شود (مورد بعدی برنده است):

1. `configs/default.yaml` — همهٔ بخش‌ها و مقادیر پیش‌فرض.
2. `books/<slug>/config.yaml` — بازنویسی‌های اختیاری هر کتاب.
3. متغیرهای محیطی `SHAHRZAD_*` — کلیدهای تودرتو از `__` استفاده می‌کنند، مثلاً `SHAHRZAD_BUDGET__MAX_USD=5`.
4. پرچم‌های CLI.

`.env` از ریشهٔ پروژه (یا `SHAHRZAD_HOME`) بارگذاری می‌شود و هرگز متغیر محیطی از قبل تنظیم‌شده را بازنویسی نمی‌کند. کلیدهای ناشناختهٔ پیکربندی رد می‌شوند.

فایل‌های مرجع:

- [`configs/default.yaml`](configs/default.yaml) — پیکربندی کامل پیش‌فرض.
- [`configs/sample.book.yaml`](configs/sample.book.yaml) — نمونهٔ کامل و کامنت‌دار برای هر کتاب.
- [`configs/examples/book-economy.yaml`](configs/examples/book-economy.yaml) — بودجهٔ تنگ‌تر/حالت economy.
- [`configs/examples/book-auto-glossary.yaml`](configs/examples/book-auto-glossary.yaml) — حالت واژه‌نامهٔ خودکار.
- [`configs/models/deepseek.yaml`](configs/models/deepseek.yaml) — پروفایل مدل پیش‌فرض.
- [`configs/models/local.yaml`](configs/models/local.yaml) — نقطهٔ پایانی محلی اختیاری سازگار با OpenAI (Ollama/vLLM).
- [`configs/models/example-other.yaml`](configs/models/example-other.yaml) — قالب ارائه‌دهندهٔ دیگر.

مقادیر کلیدی پیش‌فرض:

| کلید | پیش‌فرض | معنی |
|---|---|---|
| `book.translator` | `""` | فرادادهٔ اختیاری مترجم انسانی؛ خروجی‌های کتاب همیشه نشانی پروژه را نشان می‌دهند |
| `glossary.mode` | `off` | `off`، `provided` یا `auto` |
| `pipeline.analyze.brief_approval` | `auto` | برای دروازه‌گذاری بریف `manual` بگذارید (یا از `--review-brief` استفاده کنید) |
| `provider.thinking` | `disabled` | در v1 غیرفعال بماند؛ بازنویسی هر عامل به شواهد M10 نیاز دارد |
| `pipeline.cost_mode` | `auto` | `auto`، `economy`، `standard` یا `quality` |
| `budget.max_usd` | `10` | سقف هر کتاب؛ هنگام رسیدن با کد `3` متوقف می‌شود |
| `review.min_coverage_for_export` | `1.0` | دروازهٔ کامل‌بودن |
| `export.formats` | `[epub, docx, md, txt]` | قالب‌های خروجی پیش‌فرض |

## ساختار فضای کار

`shz init` این ساختار را در `books/<slug>/` می‌سازد:

| مسیر | محتوا |
|---|---|
| `book.db` | منبع حقیقت SQLite: فصل‌ها، قطعه‌ها، نسخه‌های ترجمه، ایرادها، واژه‌نامه، اجراها، کش |
| `config.yaml` | بازنویسی‌های اختیاری هر کتاب (مثلاً `glossary.mode: provided`) |
| `source/` | فایل اصلی دست‌نخورده به‌همراه فصل‌ها/تصاویر استخراج‌شده و فرادادهٔ ورود |
| `artifacts/` | دانش انسانی: `brief.yaml`/`brief.draft.yaml`، `glossary.yaml`/`glossary.candidates.yaml`، `proper_nouns.yaml`، `ledger.jsonl`، `anchors.yaml` اختیاری، `structure.yaml`، `chapter_summaries.jsonl` |
| `runs/<run_id>/` | `manifest.json`، `calls.jsonl` و `report.md` هر اجرا (هزینه، پوشش، ترمیم‌ها، پرریسک‌ترین قطعه‌ها) |
| `review/` | `report.html`، `flags.csv` و `corrections.jsonl` واردشده |
| `out/` | فایل‌های نهایی EPUB/DOCX/Markdown/متن ساده، PDF اختیاری و HTML دوزبانه |

برون‌بری‌ها تبدیل‌های فقط‌خواندنی پایگاه‌داده و مصنوعات‌اند و هرگز `book.db` را تغییر نمی‌دهند. اجرای دوبارهٔ `shz init --force` فضای کار قبلی را زیر `backups/<slug>.bak-<timestamp>/` بایگانی می‌کند و سپس از نو می‌سازد.

## سیاست هزینه و مدل

- مدل پیش‌فرض پیش‌نویس و منتقد: `deepseek-flash`، حالت تفکر **خاموش**. `standard` حالت پیش‌فرض است؛ یک کتاب ۹۰هزارکلمه‌ای به‌طور میانگین حدود ۱ تا ۲ دلار هزینه دارد.
- حالت `quality` ردهٔ کیفیت پیکربندی‌شده را برای منتقدها/بازنگر نگه می‌دارد. در پروفایل ارائه‌شده این رده `gpt-6-luna` از طریق OpenRouter است (`OPENROUTER_API_KEY`).
- حالت `economy` ویراستار ادبی را رد می‌کند؛ `auto` بر اساس اندازهٔ کتاب و سقف، حالت را انتخاب می‌کند.
- `shz estimate` هر سه حالت را در هر دو تعرفه پیش از خرج کردن گزارش می‌کند. قیمت غیراوج گزارش می‌شود، اما شهرزاد هرگز برای آن صبر نمی‌کند.
- هر فراخوانی LLM کش، انتساب و هزینه‌گذاری می‌شود. اجرای دوبارهٔ کتاب تغییرنکرده هیچ فراخوانی پولی تازه‌ای انجام نمی‌دهد.
- با رسیدن به `budget.max_usd`، اجرا وضعیتش را ذخیره و با کد `3` خارج می‌شود. پس از بالا بردن `budget.max_usd`/`--max-usd` یا دادن `--allow-overrun` همان فرمان را دوباره اجرا کنید.

## عیب‌یابی

| نشانه | کار |
|---|---|
| `shz doctor` هشدار `api_key ... missing` می‌دهد | `DEEPSEEK_API_KEY` و/یا `OPENROUTER_API_KEY` را به `.env` بیفزایید. آزمون‌های آفلاین از ارائه‌دهندهٔ ساختگی استفاده می‌کنند و کلید لازم ندارند. |
| کیفیت ورود PDF پایین است یا ترجمه آن را رد می‌کند | `shz inspect` را اجرا کنید، `artifacts/structure.yaml` را اصلاح کنید، یا `shz translate --accept-pdf-quality` را بدهید. PDFهای اسکن‌شده/فقط‌تصویری پشتیبانی نمی‌شوند (بدون OCR). |
| `epubcheck` پیدا نمی‌شود | اعتبارسنجی بیرونی اختیاری است. اعتبارسنج داخلی همیشه اجرا می‌شود و خروجی همچنان تولید می‌شود. برای فعال‌کردن بررسی بیرونی Java + epubcheck نصب کنید. |
| `soffice` پیدا نمی‌شود / `--pdf` رد می‌شود | LibreOffice را نصب کنید یا فرمان دستی چاپ‌شدهٔ `soffice --headless --convert-to pdf …` را اجرا کنید. نتیجه خواندنی است اما آمادهٔ چاپ نیست. |
| اجرا با کد `3` خارج می‌شود (توقف بودجه) | وضعیت ذخیره شده است. `budget.max_usd` یا `--max-usd` را بالا ببرید یا `--allow-overrun` بدهید و همان فرمان را دوباره اجرا کنید. |
| برون‌بری مسدود و با کد `4` خارج می‌شود (ناقص) | ترجمه را تمام کنید، ایرادهای خطای باز را حل/waived کنید (`shz qa`/`shz review`)، یا با `--allow-incomplete` یک نسخهٔ ناقص علامت‌خورده بنویسید. |
| `multiple book workspaces found` | گزینهٔ سراسری را پیش از فرمان بدهید، مثلاً `shz --book my-book translate`، یا برای هر ریشهٔ پروژه یک فضای کار بگذارید. |
| خطای ارائه‌دهنده/شبکه | کلید و اتصال را بررسی کنید؛ اجرا قابل‌ازسرگیری است و فراخوانی‌های کش‌شده دوباره صورت‌حساب نمی‌شوند. |

## محدودیت‌ها

- پانویس‌های DOCX به‌صورت **یادداشت پایانی** در هر فصل منتشر می‌شوند (python-docx API پانویس ندارد).
- PDF اختیاری یک تبدیل LibreOffice است: خواندنی، اما **آمادهٔ چاپ نیست** (کشیده/هم‌ترازی محدود و آینه‌سازی صفحه محدود).
- `epubcheck` بیرونی اختیاری است؛ اعتبارسنج داخلی ساختار آرشیو، مانیفست/ستون فقرات، برچسب‌های زبان راست‌به‌چپ، پیوندها و محتوای فعال را بررسی می‌کند.
- بدون OCR و بدون PDF اسکن‌شده. ورود PDF دارای لایهٔ متن به‌صورت بهترین تلاش است و امتیاز کیفیت ورود گزارش می‌کند.
- شعر به‌صورت بهترین تلاش حفظ می‌شود؛ جدول‌ها به‌صورت قطعه‌های ردیف‌محور ترجمه می‌شوند.
- کیفیت ادبی با QA مکانیکی غربال می‌شود؛ خوانندهٔ فارسی‌زبان انسان تنها دروازهٔ کیفیت واقعی است.
- هارنس ارزیابی M10، داور کیفیت، بسته‌های MQM/BWS و مقایسهٔ مدل‌ها در v1.0.0 **ارائه نشده‌اند**؛ `shz eval` وجود ندارد.

## توسعه

```bash
uv run ruff check
uv run mypy
uv run pytest -q                    # مجموعهٔ آفلاین (بدون کلید، بدون شبکه)
uv run pytest -q -m online          # آزمون‌های اختیاری ارائه‌دهندهٔ واقعی؛ نیازمند کلید و شبکه
```

CI فقط لینت، بررسی نوع و مجموعهٔ آفلاین (`pytest -q -m "not online"`) را اجرا می‌کند. فیکسچرها کتاب‌های مصنوعی و نوشتهٔ خود پروژه‌اند که با `tests/fixtures/build.py` تولید می‌شوند؛ هیچ متن شخص ثالثی ارائه نمی‌شود.

فایل‌های مشخصات منجمد، ورودی‌های توسعه‌اند (ارجاع‌های نام برای تغییر نام به شهرزاد به‌روزرسانی شده‌اند):

- [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) — محصول، معماری، خط لوله، نقاط عطف M0–M11.
- [`PROMPTS.md`](PROMPTS.md) — قراردادهای اعلان تولید.
- [`SCHEMAS.md`](SCHEMAS.md) — enumها، مدل‌ها، DDL اس‌کیولایت و قالب‌های مصنوعات.
- [`DECISIONS.md`](DECISIONS.md) — انتخاب‌های پیاده‌سازی و انحراف‌ها.
- [`REVIEW.md`](REVIEW.md) — بازبینی تقابلی و گزارش حل.

خط لولهٔ ارائه‌شده یک توالی قطعی و نوع‌دار از پاس‌هاست، نه یک حلقهٔ عامل آزاد؛ زیرعامل‌ها متعلق به گردش‌کار ساخت‌اند، هرگز به ترجمهٔ زمان اجرا.

## منشأ و حقوق

شهرزاد فرض می‌کند فایل منبع برای **استفادهٔ خصوصی** ارائه شده است. `book.rights_basis` پیش‌فرض `user_supplied` است و در شناسنامهٔ EPUB و مانیفست اجراها ثبت می‌شود؛ فقط اطلاع‌رسانی است و هرگز مرحله‌ای را دروازه‌گذاری نمی‌کند. انتشار ترجمهٔ یک کتاب دارای حق نشر به اجازهٔ دارندهٔ حق نیاز دارد. نرم‌افزار حقوق را پاک‌سازی نمی‌کند و مشاورهٔ حقوقی نیست.

## بررسی دستی ارائه‌دهندهٔ واقعی

با کلیدهای پیکربندی‌شده، آخرین مرحلهٔ پذیرش دستی، ترجمهٔ یک فصل واقعی با پروفایل پیش‌فرض است:

```bash
uv run shz init book.epub --slug smoke
uv run shz --book smoke translate --chapters 1 --max-usd 1
uv run shz --book smoke inspect
```

هزینه، پوشش و دلیل پایان گزارش‌شده را ثبت کنید. `shz doctor` فقط حضور کلید را گزارش می‌کند (هرگز مقدارش را). مجموعهٔ آفلاین ارائه‌دهندهٔ ساختگی، از جمله `tests/integration/test_tutorial_e2e.py` برای EPUB و PDF دارای لایهٔ متن، شواهد پذیرش خودکار است.
